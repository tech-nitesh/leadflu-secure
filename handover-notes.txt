1) WHAT IS THIS APP
-------------------
LeadFlu is a mobile-first website where video editors can find client work
("gigs"). The admin (Nitesh) posts leads, and editors browse them.

There are three kinds of users:
  - FREE user / GUEST : can see only "Free" leads. PRO leads show locked.
  - PRO user          : can see everything, including PRO leads' contacts.
  - ADMIN (Nitesh)    : manages leads, creates user accounts, handles payments.

Only the admin can open the admin panel. Free and PRO users cannot.

9) AI AUTO-FILL (GEMINI, with GROQ fallback)
--------------------------------------------
- In "Lead Manager", paste the client's raw message (e.g. "Need a YouTube
  editor, 3 shorts/week, $300") and press Auto-Fill. Gemini fills the form.
- Works on the free tier (~1,500 requests/day - more than enough for this app).
- GROQ is the automatic fallback provider: if Gemini fails or is unconfigured,
  the endpoint retries with Groq before returning an error, so "AI doesn't
  work" should never happen just because one provider is down.
- Extracts ONLY details present in the message (nothing is invented); missing
  budget stays empty for the admin to fill in. Also extracts WhatsApp number,
  email, and website links.
- Env keys: GEMINI_API_KEY (Gemini), GROQ_API_KEY + GROQ_MODEL (fallback,
  default model "qwen/qwen3.6-27b" which auto-falls-back to
  llama-3.3-70b-versatile if the model id is unknown). AI_PROVIDER_FORCE
  overrides the provider (used in tests).
- Rate limit: 15 requests/min per IP, returns a friendly 429 otherwise.
- The response includes a "provider" field ("gemini" or "groq") for debugging.
- TESTING the fallback without code changes: the Groq API itself is verified
  by POSTing to https://api.groq.com/openai/v1/chat/completions with the key
  (see section 15 for the automated test, which is gated behind TEST_GROQ=1).

14) PAYMENT INTEGRATION - INDIA (side discussion, NOT built yet)
----------------------------------------------------------------
- Currently money moves on WhatsApp only (no payment gateway in the app).
- The likely future option for the Indian market is RAZORPAY:
  - Supports UPI (what most Indians use), cards, netbanking, wallets.
  - Needs a Razorpay account + KYC (business PAN/current account details).
    Until that's done, Razorpay provides a TEST mode to try it out.
  - Fees are roughly 2% for cards and a small rate for UPI (exact rates vary,
    check razorpay.com/pricing before deciding).
- What it would look like in the app: a "Buy PRO" / "Pay now" button opens
  Razorpay's payment screen; when payment succeeds (verified by webhook),
  the app automatically sets the user's plan to PRO for 30 days - same as the
  admin pressing "Upgrade to Pro" today. No manual WhatsApp step needed.
- Stripe also works in India but onboarding/KYC is heavier; for this app
  Razorpay is the simpler fit. Nothing to build until Nitesh decides to go
  ahead and gets a Razorpay account.



15) AUTOMATED TESTS (tests/ folder - added after all manual testing)
------------------------------------------------------------------
- 62 API + page tests covering the WHOLE flow: admin/user login, /api/me,
  lead create/edit/delete, contact masking (FREE/PRO/guest), admin users
  CRUD, plan upgrade/renew/downgrade, self-protection, page smoke tests, and
  8 AI extraction tests (rich message, whatsapp+website, no-budget fallback,
  missing-field defaults, auth, empty message, rate limit).
- They hit the real dev server / real Firebase project, so they need the
  dev server running:
      1. npm run dev        (keep running in another window)
      2. npm test           (in another window)
- They create temporary users/leads and delete them afterwards.
- To test the LIVE site instead of localhost:
      npm run test:prod
  (note: running it against production creates real data briefly - it cleans
   up, but avoid running it near real users).
- The admin idToken is cached to a temp file (60s TTL) and /api/login allows
  10 tries/min, so running the suite repeatedly no longer trips the login
  rate limit.
- The Groq fallback test is gated behind TEST_GROQ=1 (so it is skipped in a
  normal run, since it needs the server started with AI_PROVIDER_FORCE=groq):
      $env:AI_PROVIDER_FORCE='groq'; $env:TEST_GROQ='1'; npx next dev
      node --test --test-name-pattern="Groq fallback" tests/ai-extract.test.mjs
- NOTE: the ai-extract rate-limit test intentionally trips the 15/min endpoint
  limit for 60s, and node --test runs files in parallel, so it is the LAST
  test in its file. Rerunning the suite within a minute can 429 the AI tests;
  wait a minute.
- Useful commands: node --test "tests/*.test.mjs" runs everything.
